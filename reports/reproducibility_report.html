✓ What replicates
  • FedProx μ=0.5 achieves the highest peak F1 of the four strategies — the paper's central claim — in both runs.
  • FedProx μ=1.0 achieves the lowest std dev (most stable training) in both runs, confirming the stability-vs-peak trade-off the paper describes.
  • Mean F1 for μ=1.0 lands at 0.7280 in both runs — an exact match.
△ What diverges
  • All four strategies score ~1–1.5pp higher in this run than in the paper.
  • Best-F1 round numbers differ substantially per strategy (e.g. FedAvg: round 23 here vs. round 70 in the paper).
  • The paper reports FedAvg as the least stable strategy (highest std dev); here it's among the most stable — the ranking of "least stable" strategy does not reproduce.

This is plausible run-to-run variance inherent to Flower/Ray's client-sampling and actor-scheduling order, which a fixed torch.manual_seed does not fully pin down across processes. Reported transparently rather than adjusted to fit.

Code findings

04

Two real gaps surfaced while reproducing the pipeline — both environment/dependency issues, not logic errors. Everything else (filtering thresholds, feature engineering, ID mapping, scaling, DNN architecture, FedProx's proximal term, every Table 2 hyperparameter) matched the paper exactly.

requirements.txt is missing ray

flwr.simulation.start_simulation requires the flwr[simulation] extra, which depends on ray. A plain pip install -r requirements.txt fails with ImportError: Unable to import module 'ray' before any training starts.

→ fixed: added ray==2.6.3 to requirements.txt

Pinned flwr==1.7.0 / ray==2.6.3 cannot install on Python 3.12

ray==2.6.3 has no published wheel for Python 3.12 (Kaggle's current default runtime). The repo's own README targets Python 3.10, so this only bites on newer interpreters — worth a version-range note for anyone reproducing on a fresher Python.

→ worked around in the Kaggle notebook with unpinned flwr/ray
